# TryHackMe – Penetration Testing Frameworks

## Overview

This repository documents my learning journey through the **Penetration Testing Frameworks** room on TryHackMe, completed as part of my broader Penetration Testing Foundations studies.

The room focused on understanding how professional penetration testing frameworks help structure security assessments, guide testing activities, and communicate findings in a standardized way.

## Learning Path

This room was the final part of my learning journey covering:

- Web Pentesting
- Infrastructure Pentesting
- Penetration Testing Frameworks

## Key Learning Objectives

### 1. OSSTMM – Attack Surface Analysis

Studied the five OSSTMM security channels and their role in describing an organization's attack surface:

- HUMSEC – Human Security
- PHYSSEC – Physical Security
- SPECSEC – Spectrum Security
- COMSEC – Communications Security
- DATASEC – Data Security

The exercise reinforced the importance of assessing security beyond traditional network and application boundaries.

### 2. ISSAF – Adversarial Progression

Practiced sequencing the nine stages of an adversarial progression, from initial information gathering to maintaining access and covering tracks.

The scenario illustrated how an exposed CI/CD service could potentially lead to further compromise, including credential exposure and lateral movement.

### 3. MITRE ATT&CK – Tactic Mapping

Mapped engagement findings to MITRE ATT&CK tactics using standardized terminology.

This highlighted the importance of describing adversary behavior in a way that can be understood by penetration testers, red teams, blue teams, and threat analysts.

### 4. Framework Selection – Engagement Scenarios

Completed practical framework-selection scenarios based on different client environments and requirements:

- **UK Retail Bank:** Financial-sector assessment and regulatory considerations.
- **Regional Hospital:** Healthcare environment and compliance obligations.
- **Fintech Mobile:** iOS and Android banking applications handling cardholder data.

For the fintech scenario, the selected framework stack was:

- **Primary:** OWASP MSTG – Mobile Security Testing Guide
- **Supplementary:** PCI DSS Penetration Testing Guidelines

The exercise demonstrated how framework selection depends on the target technology, assessment scope, regulatory requirements, and expected deliverables.

## Final Exercise

The final dossier contained four practical drills inspired by real-world engagements.

The exercises focused on:

1. Identifying security channels and mapping the attack surface.
2. Understanding the progression of an adversary.
3. Mapping engagement findings to MITRE ATT&CK.
4. Selecting appropriate frameworks for client scenarios.

These exercises emphasized decision-making and methodology selection rather than simply running tools.

## Key Takeaways

This room reinforced that penetration testing is not only about identifying vulnerabilities.

A professional assessment also requires:

- A structured methodology.
- Clear understanding of the engagement scope.
- Appropriate framework selection.
- Standardized reporting and terminology.
- Awareness of regulatory and client requirements.
